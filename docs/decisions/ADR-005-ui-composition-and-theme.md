# ADR-005: UI 구성과 테마

## Status
Accepted

## Date
2026-08-16

## Context

생성 화면에는 프롬프트, 모델 선택, 복수 LoRA 선택·가중치·순서 변경, 추론 스텝과 생성 버튼이 필요합니다. 모델 관리 화면에는 저장된 리소스의 모델·LoRA·미분류 탭, 상세 정보 확인, 이름·설명·분류 변경과 삭제 진입점이 필요합니다. Expo UI Jetpack Compose는 네이티브 컨트롤을 제공하지만 화면 전체의 세밀한 디자인과 복잡한 상호작용을 Compose 컴포넌트만으로 맞추기 어렵습니다.

초기 LoRA 정렬 구현과 범용 draggable-list 라이브러리는 스크롤 점프, 드래그 중 위치 튐, 재정렬 지연을 일으켰습니다. 모델 관리 UI를 화면 파일 하나에 구현하자 상태 조정, 카드 표시, 키보드 대응 상세 모달과 스타일이 한 파일에 섞여 변경하기 어려워졌습니다. 또한 화면마다 색상을 직접 정의하면 라이트·다크 팔레트가 쉽게 어긋납니다.

## Decision

1. 화면 레이아웃, 카드, 텍스트, 선택 모달은 React Native 기본 컴포넌트로 구현합니다.
2. 슬라이더와 생성 버튼처럼 네이티브 동작이 유리한 컨트롤에만 Expo UI Jetpack Compose를 사용합니다.
3. LoRA 정렬은 이미 설치된 Gesture Handler와 Reanimated로 만든 전용 컴포넌트에서 처리합니다. 정렬 핸들을 길게 눌러 이동하며 접근성 순서 변경 액션도 제공합니다.
4. 생성 화면의 역할을 `index.tsx`의 상태 조정과 하위 컴포넌트로 분리합니다.
5. 모델 관리 화면의 상태와 이벤트 조정은 `src/app/models.tsx`에 유지하고, 카드·상세 모달·관련 타입은 `src/components/model-management.tsx`로 분리합니다.
6. 모델 관리와 생성 시 모델 선택의 책임을 분리합니다. 관리 화면은 리소스 정보와 분류를 관리하며 모델/LoRA 선택 및 LoRA 가중치 설정은 생성 화면에서 처리합니다.
7. 모델 카드를 누르면 키보드 회피와 내부 스크롤을 지원하는 하단 상세 모달을 엽니다. 이름은 명시적 변경 버튼으로 확정하고, 설명은 입력 즉시 반영하며, 자동 판별된 분류는 사용자가 직접 덮어쓸 수 있습니다. 파일 형식·크기·원본 파일명은 읽기 전용으로 표시합니다.
8. 앱 색상은 `src/constants/theme.ts`의 단일 `Colors` 객체에 `light`와 `dark` 팔레트로 정의합니다. 두 팔레트는 같은 토큰 키를 유지하고 컴포넌트는 색상 리터럴을 갖지 않습니다.
9. 현재 화면은 `Colors.dark`를 명시적으로 사용합니다. 라이트 팔레트는 정의만 하며 테마 전환 기능은 별도 작업으로 남깁니다.
10. 생성 설정과 모델 관리 변경은 현재 UI 상태에만 존재합니다. 네이티브 API와 저장소 계층이 준비될 때까지 실제 추론 인자, 파일 탐색, 메타데이터 판별, 영구 저장 또는 파일 삭제에 연결하지 않습니다.

## Alternatives Considered

### 전체 화면을 Expo UI Jetpack Compose로 구성

- 네이티브 컨트롤의 장점은 있지만 원하는 카드·목록 디자인을 맞추기 어렵고 플랫폼별 표현 제약이 큽니다.
- 화면 전체가 아니라 필요한 컨트롤에만 사용합니다.

### 범용 draggable-list 라이브러리 사용

- 빠르게 도입할 수 있지만 중첩 스크롤과 활성 행 측정 방식이 현재 생성 화면에서 반복적인 점프와 깜빡임을 만들었습니다.
- 필요한 고정 높이 세로 정렬 동작만 전용 컴포넌트로 구현하는 편이 작고 예측 가능합니다.

### 컴포넌트별 색상 상수 유지

- 파일 단위로는 간단하지만 팔레트 변경 시 누락이 생기고 라이트·다크 토큰 대응을 검증하기 어렵습니다.
- `Colors` 하나를 색상 정의의 단일 출처로 사용합니다.

### 모델 관리 UI를 화면 파일 하나에 유지

- 한 파일에서 전체 흐름을 볼 수 있지만 화면 상태, 카드 표현, 모달 입력 상태와 키보드 대응이 함께 커집니다.
- 화면은 데이터와 이벤트를 조정하고 재사용 가능한 표시·상호작용 UI는 `components`에 두는 현재 경계가 책임을 더 명확히 합니다.

### 모델 관리 화면에서 생성 모델도 선택

- 관리와 선택을 한 화면에서 처리할 수 있지만 생성 컨텍스트의 LoRA 조합과 가중치 상태가 파일 관리 책임에 섞입니다.
- 관리 화면은 저장 리소스 정리에 집중하고 선택 상태는 생성 화면이 소유합니다.

## Consequences

- UI 세부 디자인은 React Native 스타일로 자유롭게 조정하면서 필요한 네이티브 컨트롤은 유지할 수 있습니다.
- LoRA 목록은 현재의 고정 높이 세로 카드 구조에 최적화되어 있습니다. 가변 높이·대규모 가상화가 필요해지면 정렬 방식을 다시 평가해야 합니다.
- 테마 변경은 두 팔레트가 준비되어 있지만, 고정된 `Colors.dark` 참조를 선택된 팔레트로 전환하는 후속 작업이 필요합니다.
- 모델과 LoRA 설정을 실제 추론에 적용하려면 TypeScript 공개 API, Kotlin 모듈, JNI 브리지와 C++ 호출 인자를 함께 확장해야 합니다.
- 모델 관리 화면은 카드와 상세 모달을 독립적으로 변경할 수 있고, 화면 파일은 목록 필터와 선택된 항목 갱신 흐름에 집중합니다.
- 사용자가 바꾼 이름·설명·분류와 삭제는 앱 재시작 후 유지되지 않습니다. 저장소 계층을 도입할 때 현재 컴포넌트 콜백을 실제 영속화 작업에 연결해야 합니다.
- 메타데이터 자동 판별이 틀릴 수 있으므로 판별 결과와 사용자 분류를 별도로 보존해야 합니다. 사용자 분류가 다를 때는 상세 모달에서 덮어쓴 상태를 알립니다.
