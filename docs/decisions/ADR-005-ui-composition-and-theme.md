# ADR-005: UI 구성과 테마

## Status
Accepted

모델 관리 영속화 보류 결정은 [ADR-006](ADR-006-app-storage-and-model-import.md)에서 대체되었습니다. UI와 생성 화면의 책임 분리는 유지합니다.
생성 설정을 네이티브 추론에 연결하지 않았던 당시 제약은 [ADR-007](ADR-007-generation-contract-progress-and-image-storage.md)에서 해소되었습니다.
다크 테마 고정 결정은 2026-08-20의 Zustand 기반 테마 관리 구현으로 갱신되었습니다.
생성 화면의 상태 orchestration은 [ADR-016](ADR-016-generation-screen-state-model.md)에서 draft와 실행 lifecycle reducer로 구체화되었습니다.

## Date
2026-08-16

## Context

생성 화면에는 프롬프트, 모델 선택, 복수 LoRA 선택·가중치·순서 변경, 추론 스텝과 생성 버튼이 필요합니다. 모델 관리 화면에는 저장된 리소스의 모델·LoRA·미분류 탭, 상세 정보 확인, 이름·설명·분류 변경과 삭제 진입점이 필요합니다. Expo UI Jetpack Compose는 네이티브 컨트롤을 제공하지만 화면 전체의 세밀한 디자인과 복잡한 상호작용을 Compose 컴포넌트만으로 맞추기 어렵습니다.

초기 LoRA 정렬 구현과 범용 draggable-list 라이브러리는 스크롤 점프, 드래그 중 위치 튐, 재정렬 지연을 일으켰습니다. 모델 관리 UI를 화면 파일 하나에 구현하자 상태 조정, 카드 표시, 키보드 대응 상세 모달과 스타일이 한 파일에 섞여 변경하기 어려워졌습니다. 또한 화면마다 색상을 직접 정의하면 라이트·다크 팔레트가 쉽게 어긋납니다.

초기 구현은 모든 화면에서 `Colors.dark`를 직접 선택했기 때문에 `Colors.light` 팔레트가 있어도 사용자가 테마를 바꿀 수 없었습니다. 앱 재시작 후에도 선택을 유지하면서 시스템 설정, 라이트 모드와 다크 모드를 일관되게 적용할 수 있는 전역 테마 상태가 필요했습니다.

## Decision

1. 화면 레이아웃, 카드, 텍스트, 선택 모달은 React Native 기본 컴포넌트로 구현합니다.
2. 슬라이더와 생성 버튼처럼 네이티브 동작이 유리한 컨트롤에만 Expo UI Jetpack Compose를 사용합니다.
3. LoRA 정렬은 이미 설치된 Gesture Handler와 Reanimated로 만든 전용 컴포넌트에서 처리합니다. 정렬 핸들을 길게 눌러 이동하며 접근성 순서 변경 액션도 제공합니다.
4. 생성 화면의 상태와 이벤트 조정은 `src/app/index.tsx`에 유지합니다. 고급 옵션, 생성 컨트롤, 모델·LoRA 선택기와 LoRA 정렬 UI는 `src/components/generate/` 아래 컴포넌트로 분리합니다.
5. 모델 관리 화면의 상태와 이벤트 조정은 `src/app/models.tsx`에 유지하고, 카드·상세 모달·관련 타입은 `src/components/models/model-management.tsx`로 분리합니다. 히스토리도 같은 경계를 적용하여 `src/app/history.tsx`가 화면 상태와 수명 주기를, `src/components/history/history-management.tsx`가 카드와 상세 모달을 담당합니다.
6. 모델 관리와 생성 시 모델 선택의 책임을 분리합니다. 관리 화면은 리소스 정보와 분류를 관리하며 모델/LoRA 선택 및 LoRA 가중치 설정은 생성 화면에서 처리합니다.
7. 모델 카드를 누르면 키보드 회피와 내부 스크롤을 지원하는 하단 상세 모달을 엽니다. 이름은 명시적 변경 버튼으로 확정하고, 설명은 입력 즉시 반영하며, 자동 판별된 분류는 사용자가 직접 덮어쓸 수 있습니다. 파일 형식·크기·원본 파일명은 읽기 전용으로 표시합니다.
8. 앱 색상은 `src/constants/theme.ts`의 단일 `Colors` 객체에 `light`와 `dark` 팔레트로 정의합니다. 두 팔레트는 같은 의미 기반 토큰 키를 유지하며, 경고·오버레이·네이티브 컨트롤 색상을 포함해 화면과 컴포넌트는 색상 리터럴을 갖지 않습니다.
9. 테마 선택은 Zustand의 `useThemeStore`가 소유하며 `system`, `light`, `dark` 세 가지 모드를 제공합니다. 선택값은 Zustand `persist` middleware와 `@react-native-async-storage/async-storage`를 통해 앱 재시작 후에도 유지합니다.
10. 네이티브 앱의 `useColorScheme`은 저장된 모드가 `system`이면 React Native 시스템 색상 설정을 따르고, 명시적으로 선택된 경우 해당 라이트·다크 모드를 반환합니다. `useTheme`은 이 결과로 `Colors.light` 또는 `Colors.dark`를 선택하며 루트 `ThemeProvider`와 각 화면·컴포넌트가 같은 모드를 사용합니다.
11. 테마 변경 UI는 설정 화면이 담당합니다. 화면과 컴포넌트는 테마 상태 저장 방식을 직접 알지 않고 `useTheme`이 반환하는 의미 기반 색상 토큰만 사용합니다.
12. 웹은 정적 렌더링 hydration을 고려한 별도 `use-color-scheme.web.ts`를 유지합니다. 현재 웹 구현은 저장된 Zustand 모드가 아니라 브라우저의 시스템 색상 설정을 따르므로, 저장된 사용자 선택의 플랫폼 간 동기화는 보장하지 않습니다.
13. 생성 설정은 당시 UI 상태에만 존재했으며 네이티브 API 계약을 함께 확장하기 전에는 실제 추론 인자에 연결하지 않았습니다. 이 제약은 ADR-007과 ADR-010에서 해소되었고, 모델 관리 저장소의 후속 결정은 ADR-006에 기록합니다.

## Alternatives Considered

### 전체 화면을 Expo UI Jetpack Compose로 구성

- 네이티브 컨트롤의 장점은 있지만 원하는 카드·목록 디자인을 맞추기 어렵고 플랫폼별 표현 제약이 큽니다.
- 화면 전체가 아니라 필요한 컨트롤에만 사용합니다.

### 범용 draggable-list 라이브러리 사용

- 빠르게 도입할 수 있지만 중첩 스크롤과 활성 행 측정 방식이 현재 생성 화면에서 반복적인 점프와 깜빡임을 만들었습니다.
- 필요한 고정 높이 세로 정렬 동작만 전용 컴포넌트로 구현하는 편이 작고 예측 가능합니다.

### 컴포넌트별 색상 상수 유지

- 파일 단위로는 간단하지만 팔레트 변경 시 누락이 생기고 라이트·다크 토큰 대응을 검증하기 어렵습니다.
- `Colors` 하나를 색상 정의의 단일 출처로 사용합니다.

### 화면별 로컬 테마 상태

- 별도 전역 의존성 없이 구현할 수 있지만 화면 전환 시 선택을 공유하기 어렵고, 각 화면에서 시스템 설정과 영속화를 중복 처리해야 합니다.
- 테마는 앱 전체에 동시에 적용되는 사용자 설정이므로 Zustand 전역 저장소가 책임을 소유합니다.

### 시스템 테마만 사용

- 별도 설정과 영속화가 필요 없지만 사용자가 앱에서 시스템과 다른 테마를 선택할 수 없습니다.
- 시스템 추종을 기본 선택지로 유지하면서 라이트·다크 명시 선택도 제공하는 세 가지 모드를 채택합니다.

### 모델 관리 UI를 화면 파일 하나에 유지

- 한 파일에서 전체 흐름을 볼 수 있지만 화면 상태, 카드 표현, 모달 입력 상태와 키보드 대응이 함께 커집니다.
- 화면은 데이터와 이벤트를 조정하고 재사용 가능한 표시·상호작용 UI는 `components`에 두는 현재 경계가 책임을 더 명확히 합니다.

### 모델 관리 화면에서 생성 모델도 선택

- 관리와 선택을 한 화면에서 처리할 수 있지만 생성 컨텍스트의 LoRA 조합과 가중치 상태가 파일 관리 책임에 섞입니다.
- 관리 화면은 저장 리소스 정리에 집중하고 선택 상태는 생성 화면이 소유합니다.

## Consequences

- UI 세부 디자인은 React Native 스타일로 자유롭게 조정하면서 필요한 네이티브 컨트롤은 유지할 수 있습니다.
- LoRA 목록은 현재의 고정 높이 세로 카드 구조에 최적화되어 있습니다. 가변 높이·대규모 가상화가 필요해지면 정렬 방식을 다시 평가해야 합니다.
- 네이티브 앱의 테마 선택은 설정 화면에서 즉시 전체 UI에 반영되고 앱 재시작 후에도 유지됩니다.
- 컴포넌트가 `useThemeStore`를 직접 구독하지 않고 `useTheme`과 색상 토큰을 사용하므로 테마 상태 관리와 표현 계층의 결합을 제한합니다.
- 웹은 현재 시스템 색상만 따르므로 네이티브와 같은 명시적 테마 선택을 지원하려면 웹 전용 hook에 Zustand hydration 처리를 추가해야 합니다.
- 모델과 LoRA 설정의 실제 추론 연결은 ADR-007에서 TypeScript 공개 API, Kotlin 모듈, JNI 브리지와 C++ 호출 인자를 함께 확장하여 완료했습니다.
- 모델 관리 화면은 카드와 상세 모달을 독립적으로 변경할 수 있고, 화면 파일은 목록 필터와 선택된 항목 갱신 흐름에 집중합니다.
- 당시 사용자가 바꾼 이름·설명·분류와 삭제는 앱 재시작 후 유지되지 않았습니다. 이 제약은 ADR-006의 저장소 계층 도입으로 해소되었습니다.
- 메타데이터 자동 판별이 틀릴 수 있으므로 판별 결과와 사용자 분류를 별도로 보존해야 합니다. 사용자 분류가 다를 때는 상세 모달에서 덮어쓴 상태를 알립니다.
