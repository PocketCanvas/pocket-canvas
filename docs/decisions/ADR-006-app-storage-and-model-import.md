# ADR-006: 앱 저장소와 모델 가져오기

## Status
Accepted

이 문서에서 후속 범위로 둔 생성 이미지 저장소는 [ADR-007](ADR-007-generation-contract-progress-and-image-storage.md)에서 구체화되었습니다.
JSON 인덱스(`models.json`) 저장은 [ADR-020](ADR-020-sqlite-metadata-storage.md)으로 옮겨졌습니다. 문서 선택, header 검증, 실패 롤백은 유지합니다.

## Date
2026-08-17

## Context

사용자가 Android 파일 선택기에서 GGUF 또는 SafeTensors 모델을 골라 앱 전용 저장소로 가져오고, 앱을 재시작해도 별칭·설명·사용자 분류를 유지해야 합니다. 입력 파일은 신뢰할 수 없으며 확장자만 바뀐 이미지나 손상된 대용량 파일일 수 있습니다. 모델 tensor payload 전체를 JavaScript 메모리에 올리면 모바일 메모리와 배터리 비용이 큽니다.

Android 문서 선택 결과는 `content://` URI일 수 있어 URI basename만으로 원본 파일명을 알 수 없습니다. 가져오기 실패나 앱 종료가 모델 저장소에 불완전한 대용량 파일을 남겨서도 안 됩니다. 향후 생성 이미지도 영구 저장할 예정이므로 기능별 소유권이 분명한 저장소 경계가 필요합니다.

## Decision

1. Expo SDK 57의 `expo-document-picker`와 `expo-file-system`만 사용하고 별도 네이티브 모듈을 추가하지 않습니다.
2. 영구 모델은 `Paths.document/models/`에 저장합니다. 향후 이미지는 별도 디렉터리와 인덱스를 소유합니다.
3. picker가 제공하는 `asset.name`을 원본 표시 이름으로 사용하고, 앱 내부 파일명은 생성한 ID로 분리합니다.
4. 확장자는 선택 필터에만 사용합니다. 복사본의 magic/header와 tensor directory를 부분 읽기하여 GGUF 또는 SafeTensors인지 검증합니다.
5. tensor 이름에서 짝을 이룬 LoRA A/B 또는 up/down signature를 찾으면 `lora`, 전체 checkpoint signature나 GGUF architecture가 있으면 `model`, 유효한 형식이지만 확정할 수 없으면 `unknown`으로 분류합니다. VAE와 CKPT 판별은 현재 범위에 포함하지 않습니다.
6. 바이너리와 편집 가능한 메타데이터를 분리하고 `models.json` 배열에 원본 파일명, 내부 파일명, 별칭, 자동 판별값, 사용자 분류, 설명, 형식, 크기와 생성 시각을 기록합니다.
7. 가져오기는 `.importing-*` 임시 파일로 복사·검증한 뒤 최종 이름으로 이동합니다. 실패한 복사본은 삭제하며 다음 시작 시 남은 임시 파일도 정리합니다.
8. `models.json`은 임시 JSON 파일을 쓴 뒤 이동하여 교체합니다. 삭제 중 바이너리 제거가 실패하면 이전 인덱스를 복원합니다.

## Alternatives Considered

### Kotlin 네이티브 모듈에서 파일 선택과 파싱

- 대용량 파일 제어에는 유리하지만 현재 header 부분 읽기와 앱 전용 복사는 Expo API로 충족됩니다.
- 네이티브 계약과 빌드 복잡도를 늘릴 이유가 생길 때만 재검토합니다.

### 확장자만 검사

- 가장 단순하지만 이름만 바꾼 임의 파일과 손상 파일을 받아들여 신뢰 경계를 지키지 못합니다.
- 확장자는 빠른 거절에만 쓰고 실제 header 구조를 검증합니다.

### SQLite 또는 범용 데이터베이스

- 조회와 마이그레이션에는 강하지만 현재 데이터는 작은 단일 목록이고 동시 작성자도 하나입니다.
- 검색·관계·대규모 이력처럼 JSON 파일이 실제 병목이 될 때 도입합니다.

### 원본 URI를 참조하고 복사하지 않음

- 저장 공간을 절약하지만 권한 지속 여부와 외부 파일 이동·삭제에 앱 동작이 의존합니다.
- 온디바이스 추론에 안정적인 경로가 필요하므로 앱 저장소가 파일을 소유합니다.

## Consequences

- 모델 파일은 앱이 소유하므로 외부 원본이 이동하거나 삭제되어도 유지되지만 저장 공간을 추가로 사용합니다.
- header만 부분 읽어 tensor payload 전체를 JavaScript 메모리에 적재하지 않습니다. header 크기와 항목 수에도 상한을 둡니다.
- 자동 분류는 보수적 heuristic이므로 `detectedKind`와 사용자가 수정하는 `kind`를 함께 보존합니다.
- 인덱스와 바이너리는 하나의 파일시스템 트랜잭션으로 묶이지 않으므로 코드가 명시적으로 정리와 롤백을 수행합니다.
- 현재 JSON 스키마에는 버전이 없습니다. 호환성 있는 스키마 변경이 실제로 필요해질 때 마이그레이션을 도입합니다.
- 이 결정은 ADR-005의 모델 관리 영속화 보류 부분을 대체하지만 UI와 생성 화면의 책임 분리는 유지합니다.
