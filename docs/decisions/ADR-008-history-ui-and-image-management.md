# ADR-008: 히스토리 화면 구성과 생성 이미지 관리

## Status
Accepted

> ADR-013이 이 문서의 히스토리 상세 모달 제스처 구조와 전체 화면 뷰어 결정을 대체합니다. 그리드, 필터, 공유는 계속 유효합니다.
> ADR-020이 `meta.json` 인덱스 저장을 SQLite로 대체합니다. 고아 PNG 복구 정책은 유지합니다.

## Date
2026-08-18

## Context
ADR-007에서 생성된 PNG 이미지(`Paths.document/images/YYYYMMDD-HHMMSS-<id>.png`)와 `meta.json`의 저장 규격을 확정했습니다. 하지만 사용자가 생성된 결과물들을 조회하고, 검색·정렬하며, 즐겨찾기를 지정하고, 실제 이미지 파일을 다른 앱으로 공유하거나 불필요한 이미지를 안전하게 삭제할 수 있는 UI 및 관리 계층이 필요했습니다.

핵심 요구사항:
1. 기존 앱의 다크 테마(`Colors.dark`) 및 컴포넌트 구조(ADR-005)와 일관된 UI.
2. 3열 그리드 카드 및 쾌적한 렌더링 성능.
3. 탭 구성 간소화('전체', '즐겨찾기') 및 실시간 즐겨찾기 토글.
4. 단순 텍스트가 아닌 실제 PNG 이미지 파일을 외부 앱(카카오톡, 인스타그램, 갤러리 등)으로 네이티브 공유.
5. 상세 바텀시트 모달 내부에서 내용이 길어져도 끊김 없이 부드럽게 스크롤될 수 있는 제스처 계층 분리.
6. 메타데이터 쓰기가 실패했더라도 디렉토리에 남아 있는 PNG 이미지를 자동으로 복구(Reconciliation)하여 표시.

## Decision

1. **화면과 컴포넌트의 책임 분리:**
   - `src/app/history.tsx`는 화면 상태(목록, 탭, 검색어, 정렬 순서, 모달 선택 ID)와 `useFocusEffect`를 통한 자동 갱신 라이프사이클을 담당합니다.
   - 3열 그리드 카드(`HistoryCard`), 상세 바텀시트 모달(`HistoryDetailModal`) 및 관련 타입은 `src/components/history-management.tsx`에 분리합니다.

2. **탭 구성 및 즉각적인 즐겨찾기 토글:**
   - 탭은 '전체'와 '즐겨찾기' 2개로 유지하며 각 탭의 항목 수를 뱃지로 표시합니다.
   - 각 그리드 카드 우상단에 반투명 하트 오버레이 버튼을 배치하고, `event.stopPropagation()`을 통해 상세 모달을 열지 않고도 즉시 즐겨찾기 토글 및 `meta.json` 디스크 영속화를 수행합니다.

3. **네이티브 이미지 파일 공유 (`expo-sharing`):**
   - React Native 기본 `Share` 모듈은 Android에서 로컬 파일 공유 시 제약이 있으므로, Expo 공식 모듈인 `expo-sharing`을 채택합니다.
   - `Sharing.shareAsync(imageUri, { mimeType: 'image/png' })`를 호출하여 실제 PNG 이미지 파일을 안드로이드/iOS 시스템 공유 시트로 전달합니다. (공유 불가 환경에서는 텍스트/메타데이터 공유로 fallback)

4. **모달 제스처 충돌 방지 및 부드러운 스크롤:**
   - 배경 터치 닫기를 위한 `StyleSheet.absoluteFill` 투명 오버레이와 내부 `<View style={styles.sheet}>`를 명확히 분리하여, 상위 `Pressable`이 스크롤 제스처를 가로채는 문제를 차단합니다.
   - `ScrollView`의 내부 패딩(`paddingBottom: 48`)을 통해 스크롤 최하단의 '삭제' 버튼이 시스템 내비게이션 바에 가리지 않고 온전히 노출되도록 보장합니다.
   - 이 패턴은 모델 관리 모달(`ModelDetailModal`)에도 동일하게 적용하여 앱 전반의 일관성을 유지합니다.

5. **고아 이미지 파일 자동 복구 (Reconciliation):**
   - `src/lib/image-files.ts`의 `loadStoredImages()`는 `meta.json`을 읽는 동시에 `Paths.document/images/` 디렉토리를 스캔합니다.
   - 메타데이터에 등록되지 않은 PNG 파일이 발견되면 파일명 타임스탬프(`parseDateFromFileName`)를 파싱하여 복구 목록에 포함합니다.

6. **원자적 삭제 및 롤백:**
   - 이미지 삭제 시 `meta.json` 인덱스를 먼저 갱신하고 파일 시스템에서 PNG 파일을 제거합니다.
   - 파일 삭제 실패 시 이전 메타데이터 목록으로 자동 롤백합니다.

7. **필터 컨텍스트를 유지하는 전체 화면 이미지 뷰어:**
   - 그리드 카드를 누르면 상세 모달 대신 전체 화면 이미지 뷰어를 열고, 현재 탭·검색어·정렬 결과를 같은 순서로 전달합니다.
   - 사용자는 좌우 스와이프로 해당 결과 안에서 이미지를 탐색하며 하단에서 즐겨찾기, 상세 정보, 공유, 삭제를 실행합니다.
   - 이미지 확대와 페이지 전환은 `react-native-zoom-toolkit`의 `Gallery`가 하나의 제스처 상태로 소유합니다. 두 손가락 핀치로 1×~4× 확대하고, 확대 상태에서는 이미지를 이동하며, 1× 상태에서는 이전·다음 이미지로 전환합니다.
   - 네이티브 `FlatList` 스크롤과 확대 제스처를 중첩하지 않고 `Gallery`의 `windowSize=3`으로 현재·이전·다음 이미지 세 장만 렌더링합니다. 이 구조로 제스처 경쟁을 제거하고 이미지 수와 무관하게 뷰어 메모리 사용량을 제한합니다.
   - Android 네이티브 `Modal`의 별도 뷰 계층에서도 제스처가 동작하도록 모달 콘텐츠를 `GestureHandlerRootView`로 감쌉니다.
   - 상세 정보는 이미지 위의 드래그 가능한 하단 시트로 표시합니다. 드래그 손잡이와 내부 스크롤 영역을 분리하여 긴 프롬프트와 생성 옵션을 스크롤할 수 있습니다.
   - 프롬프트와 네거티브 프롬프트는 `expo-clipboard`로 복사하며 시트 안에서 복사 완료 상태를 즉시 표시합니다.
   - 즐겨찾기 탭에서 항목을 해제하거나 현재 이미지를 삭제하면 같은 위치의 다음 이미지로 이동하고, 마지막 항목이면 이전 이미지로 이동합니다.

## Alternatives Considered

### React Native 기본 Share API만 사용
- **장점:** 추가 패키지 설치 불필요
- **단점:** Android 환경에서 로컬 파일 URI(`file://`)를 실제 이미지 파일 바이너리가 아닌 단순 텍스트 URL로 취급하여 외부 메신저나 SNS로 이미지가 직접 전송되지 않음
- **기각 사유:** 사용자가 생성된 그림을 직접 공유하려는 핵심 UX를 충족하지 못하므로 `expo-sharing` 도입

### '오늘' 탭 추가 유지
- **장점:** 당일 생성물 빠른 필터링
- **단점:** 상단 탭이 3개로 늘어나며 모바일 좁은 화면에서 복잡도 증가 및 '최신순 정렬'과 기능 중복
- **기각 사유:** '전체'와 '즐겨찾기' 2개 탭으로 단순화하는 것이 더 직관적임

### `meta.json` 단독 의존
- **장점:** 파일시스템 스캔 오버헤드 없음
- **단점:** ADR-007의 "PNG 보존 우선" 원칙에 따라 메타데이터 기록이 실패한 고아 파일이 발생했을 때 히스토리 화면에 영원히 나타나지 않음
- **기각 사유:** 디렉토리 스캔을 병행하여 유실 없는 복구 메커니즘 구축

## Consequences
- 생성된 이미지가 안전하게 보존되고, 사용자가 3열 그리드에서 편리하게 탐색·검색·정렬·즐겨찾기·공유·삭제할 수 있습니다.
- `expo-sharing`을 통해 플랫폼 간 안정적인 이미지 파일 공유가 가능합니다.
- 모달 내 스크롤 제스처 충돌이 해결되어 모든 기기에서 하단 액션 버튼에 안정적으로 접근할 수 있습니다.
- 메타데이터와 파일 바이너리 간의 일관성이 보장되며 복구 내결함성을 갖춥니다.
- 그리드에서 선택한 필터와 정렬 맥락을 잃지 않고 생성 이미지를 연속 탐색할 수 있습니다.
