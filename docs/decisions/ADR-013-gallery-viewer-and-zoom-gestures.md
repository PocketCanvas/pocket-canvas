# ADR-013: 전체 화면 갤러리 뷰어와 확대 제스처

## Status
Accepted

## Date
2026-08-21

## Context

ADR-008의 히스토리 상세 모달은 한 이미지의 생성 정보를 확인하는 데 초점을 두어, 여러 생성 결과를 연속 탐색하거나 이미지를 확대할 수 없었습니다. 사용자는 현재 탭·검색·정렬 결과를 유지한 채 좌우로 이미지를 넘기고, 두 손가락으로 자연스럽게 확대하며, 즐겨찾기·상세 정보·공유·삭제를 같은 전체 화면에서 실행할 수 있어야 합니다.

일반 `FlatList`의 가로 스크롤 위에 별도의 확대 제스처를 중첩하면 Android에서 페이지 이동과 핀치가 동시에 활성화되어 이미지가 확대되면서 목록도 움직이는 충돌이 발생했습니다. 직접 만든 단순 `Pan`/`Pinch` 조합도 핀치 중심점, 실제 `contain` 이미지 경계, 확대된 이미지 끝과 다음 페이지 사이의 handoff를 완전하게 처리하지 못했습니다.

또한 React Native `Modal`은 Android에서 앱 루트와 별도의 네이티브 뷰 계층을 만들기 때문에, 앱 최상위의 `GestureHandlerRootView`만으로는 모달 내부 Gesture Handler를 활성화할 수 없습니다.

## Decision

- 그리드 이미지를 누르면 `HistoryImageViewer` 전체 화면 모달을 엽니다.
- 뷰어에는 현재 탭·검색어·정렬이 적용된 `filteredItems` 전체와 선택 ID를 전달합니다. 좌우 이동 시 현재 ID를 갱신하여 위치 표시와 하단 액션이 현재 이미지에 맞게 바뀝니다.
- 좌우 페이징과 확대는 `react-native-zoom-toolkit`의 `Gallery`가 하나의 제스처 상태로 소유합니다. 별도의 가로 `FlatList`와 확대 뷰를 중첩하지 않습니다.
- `windowSize={3}`으로 현재 인덱스 주변 항목만 렌더링하고, `initialIndex`와 `onIndexChange`로 화면 선택 상태를 연결합니다.
- 최대 배율은 4×이며 `pinchMode="clamp"`, `scaleMode="clamp"`, `allowPinchPanning`을 사용합니다. 완전한 metadata가 있는 이미지는 원본 비율과 실제 viewport로 `contain` 크기를 계산하여 확대 이동 경계를 정확히 측정하게 합니다.
- Android 모달 콘텐츠 전체를 별도의 `GestureHandlerRootView`로 감쌉니다. 이 wrapper를 제거하거나 갤러리 밖으로 옮기지 않습니다.
- 하단에는 즐겨찾기, 상세 정보, 공유, 삭제 액션을 유지합니다. 상세 정보는 드래그 가능한 하단 시트로 열고 프롬프트와 네거티브 프롬프트를 `expo-clipboard`로 복사합니다.
- 즐겨찾기 필터에서 현재 항목을 해제하거나 현재 이미지를 삭제하면 같은 시각적 위치의 다음 항목을 선택하고, 마지막 항목이면 이전 항목으로 이동합니다.
- `react-native-zoom-toolkit`은 npm 기본 범위인 `^5.1.0`을 사용하되 실제 설치 버전은 `package-lock.json`으로 재현합니다. 업데이트 후에는 Android 실기기에서 좌우 넘김, 핀치 확대, 확대 후 이동과 페이지 경계 handoff를 다시 검증합니다.

이 결정은 ADR-008의 히스토리 상세 모달 제스처 구조와 전체 화면 뷰어 관련 결정을 대체합니다. 그리드, 필터, 저장, 공유와 복구 정책은 ADR-008을 유지합니다.

## Alternatives Considered

### `FlatList`와 확대 컴포넌트 중첩

- React Native 목록 API를 그대로 사용할 수 있습니다.
- 부모 목록의 가로 pan과 자식 이미지의 pinch/pan이 경쟁하며, 확대 상태와 페이지 이동 상태를 JS에서 뒤늦게 동기화하면 Android UX가 불안정해집니다.
- 실기기에서 확대와 페이지 스크롤이 동시에 발생했으므로 채택하지 않습니다.

### 제스처 엔진 자체 구현

- 앱 요구사항에 맞게 동작을 완전히 통제하고 외부 의존성을 줄일 수 있습니다.
- 핀치 focal-point 변환, 실제 이미지 경계, 관성·스냅, 터치 수 변화, 확대 경계에서 페이지로 넘기는 handoff와 제한 렌더링을 모두 유지해야 합니다.
- 단순 구현이 실기기에서 기능 및 UX 회귀를 일으켰고, 검증된 구현과 동등한 품질을 유지하는 비용이 현재 프로젝트에 과도하여 채택하지 않습니다.

### 네이티브 이미지 뷰어

- 플랫폼에 가까운 제스처 품질을 제공할 수 있습니다.
- 새 네이티브 의존성과 빌드 구성이 필요하고 현재 React Native 오버레이 및 상세 시트 구성을 재사용하기 어렵습니다.
- TypeScript 기반 Gallery로 요구사항을 충족하므로 채택하지 않습니다.

## Consequences

- 사용자는 현재 히스토리 맥락을 유지하면서 좌우 탐색과 두 손가락 확대를 함께 사용할 수 있습니다.
- 페이징과 확대를 같은 제스처 엔진이 처리하여 부모·자식 스크롤 경쟁을 피합니다.
- `windowSize=3`으로 이미지 수가 늘어도 동시에 마운트하는 항목 수를 제한합니다.
- Gallery 동작은 외부 라이브러리와 RNGH/Reanimated/Worklets 호환성에 의존합니다.
- 라이브러리는 MIT 라이선스이고 TypeScript 소스가 배포되므로 유지보수가 중단되면 고정 버전을 유지하거나 내부 포크할 수 있습니다.
- 마이너 버전까지 허용하는 `^` 범위를 사용하므로 lockfile 갱신 시 제스처 회귀 검증이 필수입니다. `package-lock.json`을 임의로 삭제해 전체 의존성을 다시 해석하지 않습니다.
