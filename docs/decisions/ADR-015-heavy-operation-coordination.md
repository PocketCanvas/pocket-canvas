# ADR-015: 무거운 작업의 전역 조정과 메타데이터 직렬화

## Status
Accepted

`models.json`과 `images/meta.json`의 저장소별 JSON commit 큐는 [ADR-020](ADR-020-sqlite-metadata-storage.md)의 SQLite commit 큐로 옮겨졌습니다. Zustand 즉시 거절, native mutex, Expo 공용 큐 분리는 유지합니다.

## Date
2026-08-23

## Context

이미지 생성, 모델 양자화, 모델 가져오기는 CPU·GPU·메모리·스토리지 사용량이 큰 작업이다. 특히 생성과 양자화가 겹치거나 생성 요청이 연속으로 실행되면 네이티브 메모리 압박과 불명확한 실패가 발생할 수 있다. 반면 사용자는 긴 작업 중에도 히스토리 탐색, 이미지 보기·공유·즐겨찾기·삭제를 계속 사용할 수 있어야 한다.

또한 `models.json`과 `images/meta.json`은 여러 비동기 경로에서 read-modify-write하므로, 작업 자체를 막더라도 짧은 저장 구간이 겹치면 마지막 쓰기가 앞선 변경을 덮을 수 있다.

Expo Modules의 기본 `AsyncFunction`은 앱 단위의 단일 `expo.modules.AsyncFunctionQueue`를 공유한다. 생성·양자화 JNI 호출을 기본 큐에서 실행했을 때, 작업 전에 히스토리를 한 번도 열지 않은 사용자가 작업 도중 히스토리에 진입하면 최초 `File.text()`가 실행되지 못해 로딩 화면에 머무는 문제가 확인됐다. 이미 열린 히스토리의 즐겨찾기는 optimistic update 때문에 즉시 반영된 것처럼 보였지만 실제 metadata commit은 작업 종료까지 대기했다.

## Decision

- Zustand의 비영속 전역 store가 현재 무거운 작업 하나를 기록한다. 작업 종류는 이미지 생성, 모델 양자화, 모델 가져오기다.
- 작업 시작은 `tryStartOperation()`으로 즉시 획득하거나 거절한다. 대기열에 넣어 나중에 자동 실행하지 않는다.
- 작업 종료는 획득 시 받은 ID와 일치하는 `finishOperation(id)`만 잠금을 해제한다. 오래된 `finally`가 새 작업을 해제할 수 없다.
- 충돌한 동작은 시각적으로 비활성화하지만 press 이벤트는 유지해, 현재 진행 중인 작업과 재시도 시점을 안내한다.
- 무거운 작업 중에는 모델 파일이나 생성 계약을 바꿀 수 있는 가져오기, 양자화, 삭제, 이름·설명·분류 변경을 막는다. 모델 상세 조회와 히스토리의 보기·공유·즐겨찾기·삭제는 허용한다.
- 생성 진행률은 생성 화면, 양자화 진행률은 모델 관리 화면에만 표시한다. 전역 store에는 진행률을 저장하지 않는다.
- `models.json`과 `images/meta.json`에는 각각 독립적인 JS 비동기 큐를 두고 전체 read-modify-write 구간을 직렬화한다. 긴 파일 복사, 생성, 양자화는 큐 밖에서 수행하고 최종 메타데이터 commit만 큐에 넣는다.
- 네이티브 생성과 양자화는 `StableDiffusionBridge.cpp`의 mutex를 최종 방어선으로 유지한다. React 상태는 UX 조정이며 네이티브 안전성을 대신하지 않는다.
- 생성과 양자화 JNI 호출은 별도 coroutine scope에서 실행한다. Expo Modules의 공용 `AsyncFunctionQueue`를 장시간 점유하면 FileSystem·Sharing 등 다른 Expo 모듈 호출도 함께 멈추기 때문이다.
- 미완료 모델 파일 정리는 프로세스 최초 모델 로드에서만 수행한다. 진행 중 다른 화면의 로드가 활성 `.quantizing-*` 파일을 삭제하지 않게 한다.

## Alternatives Considered

### 무거운 작업을 FIFO 큐로 자동 실행

요청 시점과 실제 실행 시점 사이에 모델 선택이나 앱 상태가 달라질 수 있고, 사용자가 의도하지 않은 작업이 몇 분 뒤 시작될 수 있다. 명시적인 즉시 거절과 재시도가 더 예측 가능하다.

### Zustand만 사용

React 런타임 밖의 네이티브 호출이나 향후 다른 진입점을 보호하지 못하고, JSON read-modify-write의 유실 업데이트도 해결하지 못한다.

### 모든 앱 동작을 잠금

안전성과 관련 없는 히스토리 탐색까지 막아 긴 생성 시간 동안 앱을 사용할 수 없게 한다. 생성 계약이나 모델 파일을 변경하는 동작만 제한한다.

### 이미지 인덱스 읽기만 동기 API로 변경

히스토리의 최초 `File.text()` 대기는 피할 수 있지만 Sharing 등 다른 Expo 모듈의 비동기 호출은 계속 막히며, 장시간 연산이 공용 큐를 점유한다는 원인을 남긴다. 생성·양자화 호출 자체를 별도 큐로 분리한다.

## Consequences

- 한 프로세스에서는 무거운 작업이 하나만 시작되며, 충돌 요청은 이유를 즉시 확인할 수 있다.
- 생성 중에도 이미지 관리와 일반 탐색은 유지된다.
- 생성·양자화 중에도 FileSystem·Sharing 등 다른 Expo 모듈의 비동기 작업이 공용 큐에서 실행될 수 있다.
- 모델과 이미지 메타데이터의 동시 쓰기로 인한 변경 유실을 방지한다.
- JS 전역 상태, 메타데이터 큐, 네이티브 mutex가 서로 다른 책임을 가진다. 어느 한 계층도 다른 계층의 대체물이 아니다.
- 앱 프로세스가 비정상 종료되면 Zustand 상태는 사라지며, 다음 모델 로드에서 미완료 임시 파일을 정리한다.
